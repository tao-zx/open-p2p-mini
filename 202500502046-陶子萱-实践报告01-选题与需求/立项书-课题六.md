## 二、项目背景与选题意义

**选题背景。** Open Pixel2Play（Open P2P）是一个开源的视觉-语言-动作（Vision-Language-Action，VLA）模型项目，核心思路是让模型**直接"看"游戏画面、输出鼠标/键盘动作**，从而驱动角色在 Minecraft 等开放世界游戏中完成目标。与传统的"图像识别 + 规则决策"两段式方案不同，VLA 模型把"感知"和"动作"压缩进同一个模型，是当前具身智能与游戏 AI 领域的热门方向。

**为什么选这个课题。** 本项目作为 IEG（腾讯互动娱乐）方向的课题，贴近"AI 玩游戏"这一真实业务场景；项目提供了 150M 参数的小型基线模型和 `p2p-toy-examples` 小型样例数据，适合在有限算力和 9 天周期内完成一次完整的"数据 → 训练 → 推理 → 评估"闭环，是一次门槛可控的端到端机器学习实践。

**选题挑战与价值。** 挑战在于本机无 NVIDIA GPU、训练依赖云算力，且独立完成时间紧张；价值在于能完整走通一个真实开源 AI 项目的复现与训练流程，并产出一份可复现、可核查的实验成果。

## 三、项目目标

**总体目标：** 在 `p2p-toy-examples` 数据上复现 Open P2P 150M 模型的基线推理，使其能根据游戏画面输出动作，达到可演示、可验收的程度。

**可量化目标（对应验收）：**

| 目标 | 量化标准 |
|---|---|
| 理解模型 | 读懂 README，写清模型输入/输出/训练方式 |
| 数据就绪 | 处理 200 条数据，产出清洗样本 + 统计指标表 |
| 基线达标 | 按键准确率 ≥55%、鼠标相关系数 ≥0.5 |
| 推理验证 | 5 条测试样本输出预测动作 vs 真值对比 |
| 成果交付 | 代码 + 指标表 + 3000 字报告（含可复现步骤） |

## 四、项目范围

### 4.1 必做（MVP）

1. **模型理解**：阅读 150M 参数模型 README，输出理解说明（模型输入/输出/训练方式）。
2. **数据处理**：处理 `p2p-toy-examples` 中 200 条数据，产出清洗样本 + 统计指标表（样本数、动作分布等）。
3. **基线推理与评测**：用官方预训练 150M 权重直接推理，达到按键准确率 ≥55%、鼠标相关系数 ≥0.5（Toy 数据）。
4. **推理验证**：跑通 5 条测试数据，输出预测动作 vs 真值对比。
5. **成果交付**：提交代码 + 指标表 + 3000 字报告（含可复现步骤）。

### 4.2 不做（明确排除，防止范围蔓延）

| 不做项 | 排除原因 |
|---|---|
| 使用 `p2p-full-data` 全量训练 | 数据量大、资源不足，9 天无法完成 |
| 多模态 / 语言指令扩展 | 超出 MVP，且增加训练复杂度 |
| 生产级在线推理服务 / 部署 | 非课程要求，纯工程投入 |
| 追求 SOTA 指标 | 时间与算力不允许；拓展加分项时间允许时再评估 |

## 五、技术方案

### 5.1 技术栈

- 语言/框架：Python + PyTorch（依赖以仓库 README 的 `requirements.txt` 为准）
- 算力：学校提供的 NVIDIA 服务器（详见"风险与资源"）；本机仅用于文档与脚本编写
- 工具：CodeBuddy（辅助编码）、Git（版本管理）、JupyterLab（云端交互）、Windows 录屏（Win+G）

### 5.2 环境与脚本结构

按"数据 → 训练 → 推理"拆为三个可独立运行的脚本，接口约定如下：

| 脚本 | 输入 | 输出 |
|---|---|---|
| `preprocess.py` | `p2p-toy-examples` 原始数据 | 200 条清洗样本 + 统计指标表 |
| `infer.py` | 预训练 150M 权重 + 清洗样本 | 每帧预测动作 |
| `evaluate.py` | 预测动作 + 人类标注 | 按键准确率、鼠标相关系数 |
| `train.py`（扩展·微调） | ≤2h 微调数据（来源待定） | 微调后权重 + 前后指标对比 |

### 5.3 数据流

```
原始数据(toy) → 预处理 → 清洗样本 → 推理(预训练150M) → 预测动作 → 评测 → 对比表/指标
                        ↓                              ↓
                   统计指标表                      预测 vs 真值
```

## 六、核心用户故事与验收标准

（详细版见《需求规格-课题六.md》，此处列核心三条）

1. **作为**本组开发者，**希望**理解 Open P2P 150M 模型的输入/输出与训练流程，**以便**复现并在此基础上训练。
   - **验收句**：Given 已 clone 的仓库，When 阅读 README 并输出理解说明，Then 应写清模型输入/输出/训练方式。
2. **作为**本组开发者，**希望**把 `p2p-toy-examples` 处理成 200 条清洗样本并产出统计指标，**以便**为训练提供可复用数据。
   - **验收句**：Given 数据已就绪，When 运行预处理脚本，Then 应产出 ≥200 条样本及统计指标表。
3. **作为**课程验收方，**希望**运行训练命令后得到按键准确率 ≥55%、鼠标相关系数 ≥0.5 的模型，**以便**核对训练是否达标。
   - **验收句**：Given 清洗数据，When 运行训练命令至完成，Then 按键准确率 ≥55%、鼠标相关系数 ≥0.5。
