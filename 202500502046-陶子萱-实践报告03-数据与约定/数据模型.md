# 数据模型（第 3 天 · 数据与约定）

> 主路径上要持久化的数据。按老师要求，实验类课题按“数据切片、指标记录”等对象写，不必套 Web 分层。字段名来自官方仓库源码（附出处），并已做“对照需求删冗余”审查。

## 一、主路径是什么

第 1 天定下、第 5 天必须演示的主路径：

```
toy 原始数据 → 预处理 → 清洗样本(200 帧) → 推理(150M) → 预测动作 → 评测 → 指标 → 演示
```

主路径上有**三个**要持久化的对象：

- **原始数据**（输入，preprocess 读入）
- **样本切片**（预处理产物，推理与评测共用）
- **指标记录**（评测产物，即验收判据）

## 二、需求对照审查（删了哪些字段、为什么）

老师要求“对照需求删掉用不到的表与字段”。本课题验收只做三件事：① 处理 200 帧（与训练/微调数据隔离）出统计表；② 算按键准确率 + 鼠标相关系数（鼠标也可用位移误差，二选一）；③ 在同一测试片段上做“模型输出 vs 人类标注”对比演示。据此逐字段审查：

| 字段 | 验收用不用得到 | 结论 |
|---|---|---|
| video_id | 评测不追溯样本来源 | ❌ 删 |
| env | 只用 toy、不分环境 | ❌ 删 |
| frame | 推理的输入 | ✅ 保留 |
| keys | 算按键准确率 | ✅ 保留 |
| mouse_buttons | 两个指标都不算它 | ✅ 保留（动作本体，注明不参与指标） |
| mouse_delta_x / y | 算鼠标相关系数 | ✅ 保留 |
| is_user_action | 记录该帧动作取系统（false）还是用户（true），见说明 2 | ✅ 保留 |

## 三、实体与字段

### 实体 0：原始数据 RawData（输入，preprocess 读入）

| 字段 | 含义 | 出处 |
|---|---|---|
| video_file（.mp4） | 游戏画面视频，192×192 | 官方数据格式 |
| annotation_file（.proto） | 逐帧动作标注（`VideoAnnotation`） | 官方 proto |

> 实测（第 4 天晚冒烟测试核实）：toy 数据 = 3 段视频，每段一个 `192x192.mp4`（另有原始 `video.mp4` 为未缩放版，本课题不用）+ 一个 `annotation.proto`；帧数 2456 / 18790 / 21930（共约 4.3 万帧），fps=20。**"200 帧测试集"= 选 1 个 run（单一游戏）连续取前 200 帧**（第 5 天修正：对齐课题"单一游戏测试集连续 200 帧"；初版"各视频帧数比例均匀采样"破坏帧间时序，会拉低行为克隆评估指标）。

### 实体 1：样本切片 Sample（含逐帧动作 FrameAction）

对应“清洗样本”——从原始视频切出的帧 + 逐帧人类动作标注。**1 条 = 1 帧画面 + 1 条动作标注，200 条 = 200 帧测试集。**

| 字段 | 类型 | 含义 | 出处 |
|---|---|---|---|
| frame | 图片（192×192 彩色） | 一帧游戏画面 | 官方 `frame_height=192`、`frame_width=192` |
| action | FrameAction | 这一帧的人类动作标注 | 官方 `frame_annotations` |

**逐帧动作 FrameAction**（评测直接用它，是本课题最核心的字段）：

| 字段 | 类型 | 含义 | 出处 |
|---|---|---|---|
| keys | 列表 | 该帧按下的键盘键码 | 官方 `action_label_video_proto_dataset.py`（system_action 优先，见说明 2） |
| mouse_buttons | 列表 | 该帧按下的鼠标键码 | 同上 |
| mouse_delta_x | 整数 | 鼠标水平位移（像素） | 同上 |
| mouse_delta_y | 整数 | 鼠标垂直位移（像素） | 同上 |
| is_user_action | 布尔 | 该帧动作取系统（false）还是用户（true） | 官方 `frame_annotations[i].user_action` / `.system_action` 两独立字段 |

> 说明 1：`mouse_buttons` 是动作本体的一部分（模型会预测它），但两个验收指标都不算它——按键准确率看 `keys`，鼠标相关系数只看 `mouse_delta_x/y`。
> 说明 2（第 5 天修正）：GT 动作取 **system_action 优先**——`if system_action.is_known` → 用 system，`elif user_action.is_known` → 用 user，都未知 → 空动作，对齐官方 `action_label_video_proto_dataset.py:168-189`。初版"只取 user_action"是错的（会让 teacher_forcing 从 95%+ 掉到 23.5%）。`is_known=false` 表示该帧动作未可靠标注，评测时跳过。

### 实体 2：指标记录 MetricRecord

评测跑完得出的两个数字，是验收判据，第 5 天演示与结课报告都从这里取值。

| 字段 | 类型 | 含义 | 验收阈值 |
|---|---|---|---|
| key_accuracy | 小数 | 按键准确率 | ≥55% |
| mouse_correlation | 小数 | 鼠标相关系数（位移相关） | ≥0.5 |
| n_samples | 整数 | 评测样本数 | 200 |
| action_distribution | 表 | 动作分布（各键 / 各鼠标键频次） | 供统计表 |

> 口径说明：`n_samples = 200`（= 200 帧 = 200 条）是评测集大小；演示用”同一测试片段”（模型输出 vs 人类标注对比，必做4），与 `n_samples` 无关。**验收指标用 teacher_forcing 口径**（把 GT 动作填历史窗口、一次前向预测，行为克隆标准评估；见 接口约定.md infer.py 的 `--mode`），不是 free_running 流式（流式误差累积，key_acc 天然偏低）。

## 四、字段一致性

老师要求三处字段名一致（本课题：preprocess 产出 → infer 读入 → evaluate 读入）。统一用上表英文名（`keys` / `mouse_buttons` / `mouse_delta_x` / `mouse_delta_y`），与官方代码同名，无需另做字段对照表。

## 五、出处说明

字段全部来自官方仓库源码（已核对）：

- `elefant/data/video_proto_dataset.py`：视频 + proto 存储方式、`metadata.id`、`frame_annotations`、`frame_height=192` / `frame_width=192`。
- `elefant/data/action_label_video_proto_dataset.py`：逐帧动作字段 `keyboard.keys`、`mouse.buttons_down`、`mouse.mouse_delta_px`，转张量后的四字段 `keys` / `mouse_buttons` / `mouse_delta_x` / `mouse_delta_y`；以及 `user_action` / `system_action` / `is_known` 的区分逻辑。
