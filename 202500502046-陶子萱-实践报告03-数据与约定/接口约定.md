# 接口约定（第 3 天 · 数据与约定）

> 写入仓库、供各脚本共同遵守的调用说明。每个脚本写清：命令（方法）、参数、成功与失败时返回什么。未写明的行为不得各自猜测。

## 一、退出码规则（统一约定）

| 退出码 | 含义 |
|---|---|
| 0 | 成功 |
| 2 | 参数错误（参数缺失 / 值非法） |
| 3 | 数据/文件错误（文件不存在 / 内容对不上） |

## 二、主路径与“最关键的一步”

主路径四步：数据准备 → 推理 → 评测 → 演示。其中**最关键的一步是 `infer.py`（推理）**——它是“看画面 → 出动作”的核心，也是第 5 天演示的主角。下面把它作为完整范例写清，其余脚本用同一格式。

## 三、脚本调用约定

### 1. `infer.py` —— 推理（主路径最关键一步，完整范例）

- 命令：`python infer.py --weights <150M权重> --samples <samples.json> --out <预测目录> [--mode teacher_forcing|free_running] [--official-repo <open-p2p仓库>] [--config <配置yaml>]`
- 参数：
  - `--weights`：150M 模型权重文件路径
  - `--samples`：preprocess 产出的 `samples.json` 文件
  - `--out`：预测输出目录
  - `--mode`：`teacher_forcing`（默认，评测指标用：把 GT 动作填历史窗口一次前向）/ `free_running`（流式演示用：逐帧自主预测，误差累积）
  - `--official-repo`：官方 open-p2p 仓库根目录（含 `elefant` 包），未 `pip install -e` 时必给
  - `--config`：150M 配置 yaml，默认取 `--weights` 同目录 `model_config.yaml`
- 成功返回：退出码 0；写出 `predictions.json`（每帧的 `keys` / `mouse_buttons` / `mouse_delta_x` / `mouse_delta_y`）
- 失败返回：退出码非 0；stderr 打印原因

**成功一例：**

- 输入要点：`--weights` 指向已下载的 150M 权重；`--samples` 指向 `samples.json`（200 条样本）
- 输出要点：`predictions.json`，200 帧每帧 4 个动作字段（`keys` / `mouse_buttons` / `mouse_delta_x` / `mouse_delta_y`）

```
$ python infer.py --weights ckpt/150m.pt --samples out/samples.json --out pred
[OK] 推理 200 帧完成
[OK] 写出 pred/predictions.json
```

**失败一例（权重文件缺失）：**

```
$ python infer.py --weights no_ckpt.pt --samples out/samples.json --out pred
[ERROR] 权重文件不存在: no_ckpt.pt（退出码 3）
```

### 2. `preprocess.py` —— 数据准备

- 命令：`python preprocess.py --data_dir <toy数据> --out_dir <输出> --n_frames 200`
- 参数：
  - `--data_dir`：toy 数据目录（含 `.mp4` 视频 + `.proto` 标注）
  - `--out_dir`：输出目录
  - `--n_frames`：测试集帧数，默认 200
  - 帧尺寸固定 192×192，写死在代码里，不再作为参数
- 成功返回：退出码 0；写出 `samples.json`（帧 + 动作标注）与 `stats.csv`（统计表）
- 失败返回：退出码非 0；stderr 打印原因

**成功一例：**

- 输入要点：`--data_dir` 指向含 `.mp4` + `.proto` 的 toy 目录，`--n_frames 200`
- 输出要点：`samples.json`（200 条样本）+ `stats.csv`（样本数 / 动作分布）

```
$ python preprocess.py --data_dir toy-examples --out_dir out --n_frames 200
[OK] 处理 200 帧 → 产出 200 条样本
[OK] 写出 out/samples.json、out/stats.csv
```

**失败一例（参数错误）：**

```
$ python preprocess.py --data_dir toy-examples --out_dir out --n_frames -5
[ERROR] --n_frames 必须是正整数，收到 -5（退出码 2）
```

**失败一例（数据目录不存在）：**

```
$ python preprocess.py --data_dir no_such_dir --out_dir out
[ERROR] 数据目录不存在: no_such_dir（退出码 3）
```

### 3. `evaluate.py` —— 评测

- 命令：`python evaluate.py --pred <predictions.json> --label <samples.json>`
- 参数：
  - `--pred`：infer 产出的 `predictions.json`
  - `--label`：preprocess 产出的 `samples.json`（内含真人标注）
- 成功返回：退出码 0；打印两个指标，写出 `metrics.json`
- 失败返回：退出码非 0；stderr 打印原因

**成功一例：**

- 输入要点：`--pred` 与 `--label` 两个文件，帧数一致
- 输出要点：按键准确率 + 鼠标相关系数 + `metrics.json`

```
$ python evaluate.py --pred pred/predictions.json --label out/samples.json
[OK] 按键准确率 = 88.0% （阈值 55%，评测 200 帧）
[OK] 鼠标相关系数 = 0.756 （阈值 0.5，x=0.741 / y=0.772）
[OK] 写出 metrics.json
```

**失败一例（预测与标注 frame_id 对不上，没有可评测的帧）：**

```
$ python evaluate.py --pred pred/other_predictions.json --label out/samples.json
[ERROR] 没有可评测的帧（标注帧全部 is_known=false？）（退出码 3）
```

### 4. `train.py` —— 微调（扩展，第 6 天落地）

- 命令：`python train.py --weights <150M权重> --data_dir <2h数据子集> --out_dir <输出目录> [--official-repo <open-p2p仓库>] [--config <配置yaml>] [--n_steps N] [--freeze_steps N] [--freeze_tokenizer] [--lr_schedule constant|cosine] [--warmup_steps N] [--lr X] [--weight_decay X] [--save_every N] [--compile]`
- 参数：
  - `--weights`：150M 预训练权重（`.ckpt`，微调起点）
  - `--data_dir`：微调数据目录（1 款游戏 2 小时子集，含 `.mp4` + `.proto`）
  - `--out_dir`：输出目录
  - `--official-repo`：官方 open-p2p 仓库根目录（含 `elefant` 包），未 `pip install -e` 时必给
  - `--config`：配置 yaml，默认取官方 `config/policy_model/150M.yaml`
  - `--n_steps`：微调步数，默认 1000
  - `--freeze_steps`：冻结 transformer 层的前 N 步（0=全量微调），默认 0
  - `--freeze_tokenizer`：冻结图像 tokenizer（17.4M 帧编码器，游戏无关），只微调 transformer + 动作头（第 7 天换方法，防灾难性遗忘）
  - `--lr_schedule`：学习率调度，`constant`（默认，官方常数 LR）/ `cosine`（warmup + cosine 衰减；第 7 天换方法）
  - `--warmup_steps`：cosine 调度下的 warmup 步数，默认 0=无 warmup
  - `--lr`：覆盖微调学习率，默认 None=用 150M.yaml 的 1e-4；微调建议降到 3e-5 防灾难性遗忘
  - `--weight_decay`：覆盖权重衰减，默认 None=用 150M.yaml 的 1e-4
  - `--save_every`：每多少步存一次 checkpoint，默认 100
  - `--compile`：启用 `torch.compile`（默认关闭走 eager，因服务器缺 Python.h）
- 成功返回：退出码 0；写出最终权重（ModelCheckpoint 快照 `checkpoints/checkpoint-{step:08d}.ckpt`）+ `train_summary.json`（摘要，含 `freeze_tokenizer` / `lr_schedule` / `warmup_steps`）+ `logs/`（CSV 训练日志）
- 失败返回：退出码非 0；stderr 打印原因
- ⚠️ 注意（第 7 天已修）：旧版 `trainer.save_checkpoint` 写出的 `finetuned.ckpt` 被 `infer.py` 加载时会报 `block_mask 在 cpu、q/k/v 在 cuda`（flex_attention device 不匹配）。第 7 天起 train.py 不再写 `finetuned.ckpt`，最终权重直接改指 ModelCheckpoint 同款快照（可被 `load_from_checkpoint` 正常加载）。**评测请用 `checkpoints/` 里的周期快照**（如 `checkpoint-00000700.ckpt`）。

**成功一例（第 6 天真实运行：GTA 2h 子集，LR 3e-5 / 700 步）：**

- 输入要点：`--weights` 指向 150M 权重；`--data_dir` 指向已解压的 GTA 2h 子集（含 `.proto`）；`--lr 3e-5` 降学习率防灾难性遗忘
- 输出要点：`finetuned.ckpt` + `train_summary.json` + `checkpoints/`（每 100 步存 `checkpoint-{step:08d}.ckpt`）

```
$ python train.py --weights checkpoints/150M/checkpoint-step=00500000.ckpt \
  --data_dir data/gta-2h --out_dir out/finetune-gta --official-repo <open-p2p仓库> \
  --n_steps 700 --lr 3e-5 --freeze_steps 0
[OK] 数据目录含 5 个 .proto（data/gta-2h）
[OK] torch.compile 已关闭（force_eager）
[OK] 从 150M 权重加载模型: checkpoints/150M/checkpoint-step=00500000.ckpt
[OK] 覆盖微调学习率 = 3e-05
[OK] 开始微调：700 步，数据 data/gta-2h
[OK] 微调完成，最终权重 out/finetune-gta/checkpoints/checkpoint-00000700.ckpt
[OK] 写出 out/finetune-gta/train_summary.json
```

**换方法一例（第 7 天 · 冻图像 tokenizer + cosine 调度，应对 2h 子集微调退化）：**

```
$ python train.py --weights checkpoints/150M/checkpoint-step=00500000.ckpt \
  --data_dir data/gta-2h --out_dir out/finetune-gta-cosine --official-repo <open-p2p仓库> \
  --n_steps 700 --lr 3e-5 --freeze_tokenizer --lr_schedule cosine --warmup_steps 100
[OK] 学习率调度 = cosine（warmup 100 步，peak_lr 3e-05）
```

**评测微调结果（务必用周期快照，不用 `finetuned.ckpt`；`--samples` 用该游戏测试段的 samples.json，与训练数据隔离）：**

### 5. `prepare_finetune_data.py` —— 微调数据准备（扩展，第 6 天落地）

- 命令：`python prepare_finetune_data.py [--start N] [--end N] [--game <env_name>] [--hours N] [--exclude UUID,...] [--out_dir <目录>] [--repo <仓库>]`
- 参数：
  - `--start` / `--end`：下载的 batch 范围（含），默认 166~168（COD 密集 batch 167 ± 1 兜底）
  - `--game`：目标游戏 `env_name`，默认 `call-of-duty-mobile`
  - `--hours`：截取时长（小时），默认 2.0
  - `--exclude`：逗号分隔的要排除的 recording UUID，默认排除测试段 `01993060-…`（防泄漏）
  - `--out_dir`：输出微调数据目录，默认 `data/codm-2h`
  - `--repo`：full-data 数据集仓库，默认 `elefantai/p2p-full-data`
- 成功返回：退出码 0；写出 `<game>-N小时` 的 recording 子集（`<uuid>/annotation.proto` + `192x192.mp4`）+ `manifest.json`（选中 UUID / 帧数 / 总时长明细）
- 失败返回：退出码非 0；stderr 打印原因
- 依赖：`huggingface_hub` + `pyarrow`，仅在服务器（有网络 + 磁盘）运行

**成功一例：**

```
$ python prepare_finetune_data.py --start 166 --end 168 --game call-of-duty-mobile --hours 2
[OK] 读 parquet：_ft_download/data_metadata.parquet，108851 个 UUID key（列 ['id', 'filepath']）
[OK] 选中 24 条 call-of-duty-mobile recording，共 144123 帧 = 2.00h（目标 ~2.0h / 144000 帧）
[OK] 微调数据就绪：data/codm-2h（24 条，manifest.json 记录明细）
```

**失败一例（batch 范围内无目标游戏）：**

```
$ python prepare_finetune_data.py --start 1 --end 2 --game no-such-game
[ERROR] 过滤后无 recording（game=no-such-game），检查 batch 范围/游戏名（退出码 3）
```
