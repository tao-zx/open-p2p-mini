## 一、数据模型（主路径实体与字段）

主路径（第 1 天定、第 5 天演示）：

```
toy 原始数据 → 预处理 → 清洗样本(200 帧) → 推理(150M) → 预测动作 → 评测 → 指标(按键准确率/鼠标相关系数) → 演示
```

按老师要求，实验类课题按「数据切片、指标记录」对象写，不必套 Web 分层。主路径上持久化**三个**对象：原始数据（输入）、样本切片（预处理产物）、指标记录（评测产物）。字段已按老师「对照需求删冗余」审查：删掉验收用不到的 `video_id`、`env`。

### 实体 0：原始数据（输入，preprocess 读入）

| 字段 | 含义 | 出处 |
|---|---|---|
| video_file（.mp4） | 游戏画面视频，192×192 | 官方数据格式 |
| annotation_file（.proto） | 逐帧动作标注（`VideoAnnotation`） | 官方 proto |

### 实体 1：样本切片 Sample（含逐帧动作 FrameAction）

对应「清洗样本」——从原始视频切出的帧 + 逐帧人类动作标注。**1 条 = 1 帧画面 + 1 条动作标注，200 条 = 200 帧测试集。**

| 字段 | 类型 | 含义 | 出处 |
|---|---|---|---|
| frame | 图片（192×192 彩色） | 一帧游戏画面 | 官方 `frame_height=192`、`frame_width=192` |
| action | FrameAction | 这一帧的人类动作标注 | 官方 `frame_annotations` |

**逐帧动作 FrameAction**（评测直接用它）：

| 字段 | 类型 | 含义 | 出处 |
|---|---|---|---|
| keys | 列表 | 该帧按下的键盘键码 | 官方 `user_action.keyboard.keys` |
| mouse_buttons | 列表 | 该帧按下的鼠标键码 | 官方 `user_action.mouse.buttons_down` |
| mouse_delta_x | 整数 | 鼠标水平位移 | 官方 `user_action.mouse.mouse_delta_px.x` |
| mouse_delta_y | 整数 | 鼠标垂直位移 | 官方 `user_action.mouse.mouse_delta_px.y` |
| is_user_action | 布尔 | 是否人类动作（区分系统动作） | 官方 `user_action.is_known` |

说明：① `mouse_buttons` 是动作本体（模型会预测它），但两个验收指标都不算它——按键准确率看 `keys`，鼠标相关系数只看 `mouse_delta_x/y`；② 评测只取 `is_user_action = 真` 的人类动作，忽略系统动作（如镜头自动旋转），避免误判。

### 实体 2：指标记录 MetricRecord

对应「评测结果」，是验收判据的持久化对象，演示与结课报告都从这里取值。

| 字段 | 类型 | 含义 | 验收阈值 |
|---|---|---|---|
| key_accuracy | 小数 | 按键准确率 | ≥55% |
| mouse_correlation | 小数 | 鼠标相关系数（位移相关） | ≥0.5 |
| n_samples | 整数 | 评测样本数 | 200 |
| action_distribution | 表 | 动作分布统计 | 供统计表 |

> 口径说明：`n_samples = 200`（= 200 帧 = 200 条）是评测集大小；「5 条」是另一回事——从 200 条里挑 5 条做「预测 vs 真值」对比演示（必做4），不算进 `n_samples`。

字段一致性：三处（preprocess 产出 / infer 读入 / evaluate 读入）字段名统一为英文名（`keys` / `mouse_buttons` / `mouse_delta_x` / `mouse_delta_y`），与官方代码同名，无需另做字段对照表。

## 二、接口约定

本课题是 CLI 脚本，接口约定 = 命令 + 参数 + 成功/失败返回。约定统一退出码：0=成功、2=参数错误、3=数据/文件错误。主路径四步中，**最关键的一步是 `infer.py`（推理）**，作为完整范例：

**`infer.py` 成功一例：**

- 输入要点：`--weights` 指向 150M 权重；`--samples` 指向 `samples.json`
- 输出要点：`predictions.json`，每帧 4 个动作字段

```
$ python infer.py --weights ckpt/150m.pt --samples out/samples.json --out pred
[OK] 推理 200 帧完成
[OK] 写出 pred/predictions.json
```

**`infer.py` 失败一例（权重缺失）：**

```
$ python infer.py --weights no_ckpt.pt --samples out/samples.json --out pred
[ERROR] 权重文件不存在: no_ckpt.pt（退出码 3）
```

其余脚本同格式，失败例覆盖「参数错误」与「缺文件」两类：

| 脚本 | 命令 | 成功返回 | 失败返回 |
|---|---|---|---|
| `preprocess.py` | `--data_dir` `--out_dir` `--n_frames 200` | 退出码 0，写出 samples.json + stats.csv | 参数错(退出码 2) / 目录不存在(退出码 3) |
| `evaluate.py` | `--pred` `--label` | 退出码 0，打印两指标 + 写 metrics.json | 帧数不一致 → 退出码 3 |

`train.py`（微调）留接口、暂不落地；数据来源已确认：从 full-data 下载「1 款游戏 ≤2h」子集（不下载全库）。
