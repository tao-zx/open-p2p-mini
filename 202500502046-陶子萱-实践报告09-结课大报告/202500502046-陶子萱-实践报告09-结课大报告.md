## 2. 目标与范围

**使用场景**：让模型看着游戏画面直接输出键盘与鼠标操作，属于模仿学习（imitation learning）中的行为克隆（behavior cloning）。面向游戏自动化测试、无障碍操作，往远看是通用图形界面智能体的雏形。本课题落地在 COD（《使命召唤手游》）移动射击场景：输入一帧游戏画面，输出“按哪些键 + 鼠标往哪移”。

**必做（最终表述，以本节为准）**：

1. 跑通官方 150M 预训练模型的推理脚本，README 可复现。
2. 处理 200 条 toy 数据（与训练/微调数据隔离）并出统计表。
3. 评测达标：按键准确率 ≥55%、鼠标相关系数 ≥0.5。
4. 同一测试片段“模型输出 vs 人类标注”录屏对比。
5. 归档代码、指标表、3000 字以上报告。

**不做**：`p2p-full-data` 全库下载、多模态扩展、生产部署、追 SOTA。

**立项扩展**：微调 1 款游戏 2 小时数据子集，目标按键准确率 +8 个百分点或鼠标相关系数 +0.08。第 8 天老师口头放宽为“跑通就好”，本报告以“跑通、但增益未达线”如实记录。

## 4. 方案与主路径

**总体划分**：两条路径。**主路径**（真实实现，验收靠它）——toy 原始数据 → 预处理 → 200 帧清洗样本 → 150M 模型推理 → 预测动作 → 评测 → 指标。**扩展路径**——微调：`prepare_finetune_data.py` 切 2 小时子集 → `train.py` 训练 → 用 `infer.py` 加载微调权重复评。

**主路径贯通（入口到结果）**：

```text
data/p2p-toy-examples (原始 .proto + mp4)
  → preprocess.py --data_dir ... --n_frames 200   # 清洗 + 选段 + 出统计表
  → out/samples.json                              # 200 帧样本（含 GT 动作）
  → infer.py --weights 150M --samples ... --mode teacher_forcing
  → pred/predictions.json                         # 模型预测动作
  → evaluate.py --pred ... --label ...            # 算按键准确率 / 鼠标相关系数
  → metrics.json  →  88.0% / 0.756
```

- **模型**：官方 150M 预训练权重（`checkpoint-step=00500000.ckpt`，2.2GB）+ `model_config.yaml`；约 183M 参数 = image_tokenizer（17.4M）+ transformer + 动作头（其余 165M 可训练）。
- **读帧**：`torchcodec`（RGB），不用 `cv2`（BGR），避免颜色通道口径与官方不一致。
- **测试集**：单一游戏（1 个 run）连续 200 帧，用滑动窗口选“动作最丰富”的一段（按键种类 ×10 + 鼠标位移/点击加分），避免选到太简单、指标虚高的片段；当前测试集 = COD《使命召唤手游》第 1990~2189 帧，toy 数据为 full-data 子集，与微调数据无泄漏。
- **GT 动作口径**：`system_action` 优先，未知回退 `user_action`，都未知则空动作（对齐官方 `action_label_video_proto_dataset.py`）。
- **两种推理模式**：`teacher_forcing`（验收，每步用真实历史做一次前向）；`free_running`（演示，逐帧自回归、误差累积，天然偏低）。验收之所以用 teacher_forcing，是因为它每步都喂真实历史，把“误差累积”这个无关因素隔离掉，测的是模型单步模仿的净能力、能公平反映上限；free_running 则完全自主、无历史兜底，反映端到端自主运行的真实现状。两者分别回答“模型会不会”和“模型自主跑起来怎么样”两个不同问题。
- **环境**：NVIDIA Quadro RTX 6000 24GB + open-p2p venv（torch 2.11+cu128、torchcodec、protobuf），依赖以 `pyproject.toml` + `依赖清单.md` 固定、`uv sync --extra gpu` 一键复现。

**工作流程覆盖的办事场景**：第 5 天“主路径贯通”场景的工作流，覆盖了从数据准备到推理、评测的端到端链路，以及异常路径（参数错 / 数据错以退出码 2/3 退出）和扩展路径（微调权重加载）。这条工作流不是只跑通 happy path，而是连同失败路径一起可复现。

**harness 落在哪些文件、管住了什么**：第 6 天搭建的 harness 交接文档体系落地在仓库根目录，采用“总则 + 多级索引”结构，让 AI 每次开新对话都能自动继承项目上下文，不靠长对话记忆。各文件分工——`CLAUDE.md`（总则 + 索引 + 高频口径速览，管开发原则与雷区）、`项目备忘.md`（管硬约束、已定口径、待决问题）、`开发日志.md`（管按天进度与变更）、`接口约定.md`（管脚本输入输出与退出码）、`数据模型.md`（管数据字段格式）、`演示说明.md` + `README.md`（管他人复现与启动）。harness 管住的是“AI 输出质量取决于上下文质量”——把约定写清、雷区标明，AI 才不容易跑偏，也省 token。

## 5. 测试与演示

**验证方法（按课题选取）**：

1. **指标评测**：`evaluate.py` 算两项验收指标——按键准确率（keys 集合精确匹配）、鼠标相关系数（x/y 位移 Pearson 平均）。
2. **通检（smoke_test）**：10 条固定测试 = 4 主路径 + 4 异常路径 + 2 扩展路径，逐条对退出码（0 成功 / 2 参数错 / 3 数据错）。
3. **回归**：第 8 天在改动后重跑通检，确认旧路径未被破坏。

**结果**：未微调基线按键准确率 **88.0%**（阈值 55%）、鼠标相关系数 **0.756**（阈值 0.5），x=0.741 / y=0.772，均远超门槛（采样波动下限 82% / 0.782 仍显著过线）。动作分布上，200 帧含 7 种按键、123 帧含鼠标位移（以移动/转向键为主），符合 COD 移动射击场景。通检第 8 天重跑 **10 通过 / 0 失败 / 0 跳过**，关键条目：

| # | 步骤 | 结果 |
|---|---|---|
| 1–4 | preprocess → infer(teacher_forcing) → evaluate → infer(free_running) | exit 0，通过 |
| 5–8 | `--n_frames -5` / 数据目录不存在 / 权重不存在 / 预测标注不存在 | exit 2/3，通过（退出码符合约定） |
| 9–10 | 微调权重加载（无设备不匹配）/ train.py 1 步冒烟 | exit 0，通过 |

**演示**：同一 200 帧片段生成三种输出并排对比——人类标注（真实玩家，鼠标有转向）、teacher_forcing（验收模式，转向接近人类）、free_running（逐帧自回归，鼠标保守）。teacher_forcing 一次前向即可较好复现人类操作；free_running 因自回归误差累积，实测按键 32%、鼠标相关系数 0.116（x≈0），鼠标预测趋向“不动”的保守策略——这是完全自主运行的固有代价，非 bug。据此读者可判断：系统在验收口径（teacher_forcing）下可用且达标。演示交付物为一段 720P 录屏（`202500502046-陶子萱-行为克隆游戏智能体-演示视频-720p.mp4`），PPT 讲解与软件系统展示穿插进行——讲到方案就展示对应脚本与数据流，讲到评测就给出 88.0% / 0.756 的指标结果与三段对比视频。三段对比视频可直观看到 teacher_forcing 的转向轨迹与人类接近、free_running 的鼠标趋于保守。

## 6. 问题、复盘与 AI 协作

**三个真实困难及处理**：

1. **第 5 天准确率 23.5% 不达标 → 定位为数据口径错误**。把推理换成真实实现后，按键准确率只有 23.5%，远低于 55% 门槛。起初怀疑推理代码写错，交叉验证后定位在**数据预处理层**：GT 动作只取了 `user_action`、采样方式也不对。修正为“`system_action` 优先、回退 `user_action`”后指标跃升到 97.5%，再经滑动窗口选段（避开太简单的开头段）收敛到 88%。教训：数据口径比模型代码更容易埋坑。
2. **微调四波均未达 +8pp，根因是数据规模不足**。四波分别是——COD（原测试游戏，基线 88.0%）LR 1e-4 全量微调退化到 81.5% / 83%；换 GTA（基线 69.5%）LR 3e-5，best step400 仅 +1.5pp；换方法（冻结 image_tokenizer + cosine + warmup）best 仅 +0.5pp；再降 LR 1e-5，按键均值 −0.8pp、鼠标均值 −0.052。根因用 Open P2P 本体论文（arXiv 2601.04575）的 scaling law 对齐：2 小时子集仅为该论文 8300h 训练量的 0.024%，此体量下欠拟合、+8pp 结构上不可达，换学习率治不了。**这个负结果如实归档为科学发现，而不是工程失误**——知道“边界在哪”也是收获。
3. **第 7 天把 smoke_test 从只覆盖主路径扩展到“主路径 + 扩展路径”，第一次实跑就拦住 2 个边界 bug**——train.py 1 步冒烟时 `save_every=100 > n_steps=1`，ModelCheckpoint 一次未存、`os.listdir` 抛 `FileNotFoundError`；以及用例显式传推理配置 `model_config.yaml`，触发官方 `stage3_finetune.py:119` 的 rand_augmentation 断言。另有第 6 天遗留的 `finetuned.ckpt` 设备不匹配（flex_attention 的 block_mask 在 CPU、q/k/v 在 CUDA）当日清。修正后通检 10/10 通过。这印证了“固定测试兜底”的价值——改动后不重跑通检，这些 bug 会带着进交付。

**与 AI 协作的体会**：

- **哪些提问容易得到空话或错误代码**：开放式、无约束的“帮我优化 / 改好”，以及“先写结论再补数据”的表述方式——后者第 8 天就踩过：一度把 free_running 讲成“越玩越跑偏”，核对预测数据后才发现实为“鼠标位移预测 0、按键有对有错但无单调恶化”，据此纠正为“保守策略”。
- **哪些约束更容易得到可用结果**：把任务写成“范围 + 文件 + 验收口径 + 现象与期望”四要素时最有效。例：明确“GT 用 system_action 优先”这类口径、明确“退出码 0/2/3”这类验收，得到的就是可直接落地的实现，而不是空泛方案。
- **九天里沟通方式的改进**：从“口头交代、靠对话记忆”改进为“把约定写进 harness 文档（CLAUDE.md / 项目备忘 / 接口约定），新对话先读索引再动手”。这直接提升了跨对话的一致性，也省去反复重讲上下文。

**九天用过的方法（各举一件事实）**：下任务——每个脚本先写接口约定（输入输出 + 退出码 0/2/3）再实现，把任务写成“约束、需求、范围、输出”；上下文——项目备忘与当日短计划写进仓库，新对话先读索引再动手，不依赖超长对话；质量——改动审阅后再合并，计划/执行/核对三步，排错写齐“现象、定位、根因、修复、验证”五项；交付——演示说明可复现、README 让他人能启动、通检与回归兜底。这四件事各有对应产物：`接口约定.md`、`CLAUDE.md` 索引、第 5 天 23.5% 的排错记录、`smoke_test.py` 10 条通检。

**若再有若干天，优先改进什么**：① 成规模加数据与模型（微调要有效，得突破 2 小时子集，向论文量级靠），这是指标再往上走的结构性前提；② 把 teacher_forcing 的采样波动口径定稳（改用多次采样均值或 greedy，消除 82%–88% 的波动、让指标更可复现）；③ 补多款游戏的评测，验证模型跨游戏泛化，而不只停在单一测试集。

## 7. 总结

对照完成情况收束：**做成了**——主路径端到端贯通，未微调基线按键准确率 88.0%、鼠标相关系数 0.756，远超 55% / 0.5 门槛；通检与回归 10/10 全过；harness 交接文档体系落地，项目可独立阅读、可复现。**差在哪**——立项扩展的微调四波均未达 +8pp/+0.08，根因是 2 小时子集相对论文量级欠拟合，已作为负结果如实归档；free_running 演示模式因自回归误差累积而鼠标偏保守，是自主运行的固有代价而非缺陷。整体上，必做五条全部完成、立项扩展“跑通但未达线”，与第 3 节对照表一致，无虚报、无空白勾选。九天完成 MVP 真正学到的是：把一个真实开源 VLA 模型从 README、装依赖到跑通推理评测完整走通，理解了 150M 模型“看画面 → 出键鼠动作”的端到端链路；吃透口径——评测指标由 GT 动作口径决定，一开始没读准官方口径只有 23.5%，对齐官方 system_action 后跃升到 88%，说明复现任务“读懂口径比写代码更要紧”；学会如实面对负结果，用 scaling law 给微调未达线一个结构性解释，把“边界在哪”也当成收获；还学会用 harness 文档体系沉淀约定与口径，让项目不依赖个人长对话记忆、换个 AI 或换个对话都能接着干。
